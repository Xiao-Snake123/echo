## 这是什么

《回声 Echo》是一款**双人（同屏 / 联机）叙事解谜平台游戏**。小熊和小兔一起走过七段记忆：教室、操场、球场、雨夜、路灯下的长椅、餐厅，最后是西区体育场那朵玫瑰。每一关的机制都在讲同一件事——**有些地方，一个人到不了**：踩住压力板才开的门、踩着对方起飞的喷气、把对方拽过来的那根绳、两层楼高的楼板、藏在每一层角落的照片碎片。画面是安静的夜色：深蓝的天、暖黄的路灯、会飘的萤火虫，没有敌人，也没有失败惩罚。

**技术栈**：Phaser 3 前端 + Node/Express 后端（SQLite 存档、WebSocket 联机）。

**核心体验**
- 🐻🐰 **合作不是门槛，是捷径**：高墙靠叠罗汉、缺口靠牵绳；一个人也能通关（独行模式轮流操控两个角色）。
- 🗺️ **大厅即地图**：插画风格校园地图，双人手牵手行走，走到地标按 Enter 进关。
- 🌫️ **战争迷雾**：整片云层遮挡未解锁的关，通关一关擦开一片，没走到看不见也进不去。
- 🌙 **夜色美术**：地形纯代码绘制（渐变 / 草边 / 砖缝 / 暗角）+ 远景视差，角色间推挤绝不会把人卡进墙里。

## 快速开始

> **只有一个端口：8787。** 游戏页面、后台管理、联机 WebSocket、接口全部在它上面，
> 不存在第二个前端地址。

### 如何启动

**方式 A · 一键启动（推荐，双击即可）**

| 双击 | 作用 | 用在什么时候 |
|---|---|---|
| **`启动游戏.bat`** | 自动装依赖 → 自动构建前端 → 启动服务器 → 自动打开浏览器 | 日常玩、生日当天 |
| **`开发模式.bat`** | 同样是 8787，但带热更新（改前端即时生效，改服务端自动重启） | 改代码调试时 |

⚠️ 不要在 `client/` 里跑 `npm run dev` —— 那只会起一个连不上后端的孤立页面（端口 5173）。

**方式 B · 命令行（与上面等效）**

```bash
# 1) 第一次用、或改过前端代码之后，先构建一次前端
cd client
npm install
npm run build

# 2) 启动服务器（端口 8787）
cd ../server
npm install
npm start
```

打开 <http://localhost:8787> 即可玩；后台在 <http://localhost:8787/admin>。
健康检查：<http://localhost:8787/api/health>

> 改代码调试时，服务器改用 `npm run dev`（仍在 8787，带热更新），不用 `npm start`。

### 如何停止

**方式 A · 一键停止（推荐，双击即可）**

直接双击 **`停止服务.bat`** —— 它会按端口 8787 找到进程并停掉。

**方式 B · 命令行**

在 PowerShell / 终端里执行（任选其一）：

```powershell
# 按端口停掉 8787 上的进程
Stop-Process -Id (Get-NetTCPConnection -LocalPort 8787).OwningProcess -Force
```

或（CMD）：

```cmd
for /f "tokens=5" %a in ('netstat -aon ^| findstr :8787') do taskkill /pid %a /f
```

> 如果服务器是用 `npm run keepalive` 起的（生日当天建议用这个，崩了会自动重启），
> 停止时同样把 8787 进程杀掉即可，守护进程会随之退出。

## 架构要点（改代码前必读）

### 网络模型：各管各的本地模拟

```
自己的角色 → 本地权威模拟 → 0 延迟
对方的角色 → 网络快照 + 110ms 延迟插值 → 合作游戏无感
服务器     → 只做中继，不做任何游戏逻辑
```

**这个选择决定了三件事：**

1. 手感永远不受网络影响
2. 网络延迟只影响「对方角色的显示」，所以**高延迟的穿透工具也能接受**
3. 服务器代码永远很小，不会成为瓶颈

### 物理数值是有因果的

`config.js` 里的 `GRAVITY = 1500` / `JUMP = 700` 决定了：

- 单人可跳高度 ≈ **163px**
- 叠罗汉后可达高度 ≈ **245px**

所以关卡里 **170~240px 高的平台，单人绝对上不去，必须合作**。

> 改这两个数值前请重新验算，否则所有关卡设计会一起崩。

### 降级：联机失败也要能玩

连接超时（4 秒）后会自动进入 **offline 模式**，游戏仍可完整游玩。

**这是保命设计** —— 绝对不能让「她点开一片白屏」或「卡在连接中」发生。

## 用穿透工具对外发布

### 开发期（自己看效果）

```bash
cd server
npm start        # 监听 8787
```

用穿透工具映射 **8787** 端口，得到一个 `https://xxx` 地址。

前端通过 URL 参数指定服务器地址（会自动记住）：

```
https://你的穿透地址/?server=wss://你的穿透地址
```

或者写进 `client/.env`：

```
VITE_SERVER_URL=wss://你的穿透地址
```

### 正式发布（推荐做法）

```bash
cd client
npm run build    # 产物在 client/dist
```

然后把 `client/dist` 交给服务器托管 —— **服务器会自动挂载它**（`server/index.js` 里已实现）。

这样**一个穿透端口就能同时提供页面和 WebSocket**，她只要打开一个链接。

```bash
# 构建后重启服务器
npm start
```

### ⚠️ 穿透的三个坑

1. **必须 HTTPS/WSS**
   微信内置浏览器会拦截 http 的 WebSocket。穿透工具给的必须是 `https://` 地址，对应的 WebSocket 要写 `wss://`。

2. **生日那天，你的电脑就是服务器**
   电脑休眠 / 断网 / 穿透掉线 = 游戏挂掉。所以：
   - 关闭睡眠，接上电源
   - 提前用真机在微信里完整走一遍
   - **准备好降级预案**：如果穿透挂了，她至少能打开页面进单机模式（这就是前面说的分离部署的价值）

3. **免费穿透通常限速**
   所以游戏包体要小。当前 Phaser 打包约 1.2MB（gzip 后 ~330KB），在限速下也能接受。

## 后台看板（机制⑤「我在后台看着你玩」）

`client/src/net/telemetry.js` 负责把她的行为送上来，`server/views/admin.html` 负责让你看见：

```bash
cd server && npm start
# 浏览器打开 http://localhost:8787/admin
# 用游戏里的任意一个账号登录（比如 xiaosheng）
```

页面每 5 秒自动刷新，显示三块内容：

| 区块 | 看什么 | 你能拿它做什么 |
|---|---|---|
| **在场** | 她在线吗、此刻在哪一关、最后一次动作多久前 | 她卡住的那几秒，正好发消息过去 |
| **关卡** | 每关进入/通过/离开次数、掉坑总数、最近与最快耗时 | 哪一关设计得不对，数据直接指出来 |
| **流水** | 逐條事件（进关、犹豫、掉坑、拾取、通关、离开） | 事后复盘「你在第三章停了 40 秒」 |

上报的字段刻意只到「停留时长 / 犹豫 / 掉坑次数 / 收集进度」这一层，
**不记录按键序列和坐标轨迹** —— 那是监控，不是陪伴。

> 对应的服务端接口：`POST /api/track`、`GET /api/admin/summary`、`GET /api/admin/events`。
> 未登录也允许 `/api/track`（`user_id` 记为 null），这样"她打开过链接"这件事不会丢。

   ⚠️ 只有【第一次启动】才建号，之后改无效；要重来就删掉 `server/data/echo.db`（进度会一起没）。
2. **把那封信写成你自己的话** —— `client/src/data/letter.js`。
   这是全部改动里最不该跳过的一处（详见文件头的说明）。
3. `cd client && npm run build`，然后自己完整通关一遍（`?debug=1` 解锁七关），
   一路走到结尾那封信，确认没有崩的场景、没有卡住的关卡。
4. **真机实测**：至少一台 iPhone + 一台安卓，**都从微信里打开**。
   重点验三件事：能不能打开（不是白屏）、虚拟按键能不能走、第 7 关拼图能不能拖。

### D 日：当天

5. `cd server && npm run keepalive`（**不要**用 `npm start`）。崩了会自动重启 ——
   这一天里服务器挂掉，是整个计划唯一的彻底失败方式。
6. 穿透工具映射 **8787** → 得到 https 地址。**电脑关掉睡眠、接上电源**。
7. 发链接之前最后确认一次：`https://你的地址/api/health` 返回 `{"ok":true}`。
8. 她打开之后，你来这里看：**`https://你的地址/admin`**（只有白名单账号能看）。

### 值班时看什么

| 后台哪一栏 | 意思 | 你要做什么 |
|---|---|---|
| **在场 · 最后一次动作** | 超过 1 分钟没动静 = 她卡住了 | 这时候发消息过去，比事后问她有用得多 |
| **关卡 · 离开 / 掉坑** | 哪一关把她卡住、卡了几次 | 数据会直接指出来哪一关没设计好 |
| **时间胶囊** | 她写了（不展开） | 忍住别点开，那是给一年后留的 |

### 出问题怎么办

| 症状 | 怎么处理 |
|---|---|
| 打不开 | 服务器还在跑吗（看控制台最后一行）？穿透掉了吗？ |
| **白屏** | 十有八九是旧 `index.html` 被缓存。让她下拉刷新，或加个新参数再发一次 |
| 她在某关不动 | 后台看她在哪个 `levelId`；七关都能过，通常是另一个人掉线后在等 |
| 后台 403 | 说明登录的是另一个账号。设 `ECHO_ADMIN_USERS=你的账号` |

### 数据放在哪

- 数据库 `server/data/echo.db`（**不要提交到 git**）
- 每天自动备份到 `server/data/backups/`，只留最近 7 份
- 行为流水默认留 30 天（`ECHO_EVENT_TTL_DAYS` 可调）
- **她写的时间胶囊在 `capsules` 表里，永不清理** —— 那条要留到一年后
