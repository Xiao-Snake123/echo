## 二、测试发现并已修复的真实缺陷（2 个）

### 缺陷 1：一个人先进去时，第 2 关的门永远打不开（严重）

- **现象**：登录后不创建/不加入房间、直接开始游戏（独行模式），踩上压力板后门无反应，第 2 关必卡死。
- **根因**：`LevelScene` 里门系统的"权威判定"写的是 `localCoop || !net.isOnline || net.isHost`。当**服务器连得上但房间里只有一个人**（`isOnline=true, peerPresent=false`）时，三个条件全不成立 → 没有权威端判定开门，也没有对方的广播可听 → 门锁死。电动车系统用的是 `!(isOnline && peerPresent) || isHost`（多判了 `peerPresent`），两处不一致，门系统漏了。
- **影响场景**：恰恰是她**一个人先打开链接**的时候。
- **修复**：判定补上 `!net.peerPresent`，与电动车一致。修复后实测：踩板 → `platesOn:[true,false]` → `doorOpen:[true]` → 门降下。

### 缺陷 2：地面冲刺只持续 1 帧（中等）

- **现象**：在地面上按技能键，角色抖一下就停，冲刺形同虚设。
- **根因**：`_readInput` 的 `apply()` 在角色 `update()` **之前**执行，每帧无条件把水平速度清零；冲刺速度只在技能触发那一帧设置一次，下一帧就被清掉。
- **修复**：冲刺期间在 `update()` 内**每帧重申**冲刺速度（`update` 在输入覆盖之后执行，能把速度设回来）。修复后实测位移从 2px → 118px（无头环境等效值）。

## 三、测试环境的两个已知局限（阅读数据时须知）

1. **无头渲染约 6fps**，Phaser 固定步长每帧最多补 5 步 → 物理时间被压缩到真实时间的约 55%。因此**位移类数据按比例偏小**（如移动 172px vs 理论 312px），但"是否移动、方向、相对关系"的结论不受影响；跳跃高度由速度积分决定，基本不受影响（151 vs 163）。
2. **截图会短暂冻结页面物理**，所以凡是"边动作边采样"的用例，数据采集都安排在截图之前（或用页面内原子执行），避免截图干扰测量。

**结论：涉及精确手感（冲刺距离、滞空时间）的数据，建议以真机为准；本次数据用于证明机制正确与参数方向正确。**

## 四、复现方式

```bash
# 1. 构建前端
cd client && npm run build
# 2. 启动服务器（必须重新启动：预压缩 .gz 在启动时生成，build 后不重启会失去 gzip）
cd ../server && npm start
# 3. 跑测试（在 .testtools/ 下）
node suite1.mjs   # 登录 / 房间 / 地图 / 七关巡礼
node suite2.mjs   # 能力 / 技能 / 机关
node suite3.mjs   # 联机双人 / 开场 / 结尾 / 后台 / 系统
```
